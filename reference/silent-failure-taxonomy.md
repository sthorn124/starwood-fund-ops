# Silent-failure taxonomy

Every way an operation reported success while doing something else, documented across two complete Appian Dev MCP builds, one measured evaluation of the sail CLI, and the template's own maintenance, and stated generically. The organising rule: **a success signal proves the call was accepted, never that the thing happened.** Each entry gives the trap and the working form. "(both builds)" marks a failure hit independently in both builds. Bracketed S-numbers cite the sail evaluation's measurement record in `examples/persona-verification-walkthrough.md`. Everything else was measured in one build and is expected to recur.

## A. Success signals that prove nothing

- **`COMPLETED`, `error: null`, HTTP 200, a green save, `hasErrors: false`, `diagnostics.error: null`** — each is a statement about the call, not about the environment. A process has reported COMPLETED with zero rows written, HTTP 200 has been returned by writes that changed nothing, and clean renders have shipped blank screens. Working form: verify by existence and readback — rows counted per record type, objects re-fetched, documents checked by size — and treat every status as a claim to be tested. (both builds)
- **`PauseOnError: false` with an unwired `ErrorOccurred`** makes a failed Write Records node indistinguishable from a successful one; the process still reports COMPLETED. Working form: wire `ErrorOccurred` and `Error` to process variables on every business write and gate what follows on them.
- **`updateRecordData` echoes the request, it does not read back.** Ten rows sent, ten rows returned verbatim with HTTP 200, while three of the primary keys matched no row. The same response covers "updated", "updated but invisible to your scope", and "no row matched". Working form: read rows back by existence after every update.
- **A refused or errored `testProcessModel` run is not a no-op.** Nodes upstream of the failing node have executed and may have written. Working form: after any refused run, read which nodes ran and what they wrote before assuming nothing happened.
- **A create that fails validation may or may not have persisted the object.** A failed `createProcessModelNode` has left the node behind with the payload as sent (a blind retry then fails with "already exists" and leaves an invalid node) and has also left nothing; both outcomes occur. Working form: `getProcessModelNode` first; recover with a full-replacement update or a delete; re-issue the create only if absent.
- **`ping` and `claude mcp list` prove transport, not authorization or tool surface.** `ping` returned 200 and the server listed as connected while every design-object tool was absent from the session, and an expired browser session behind the server shows the same green ping while design calls fail. So does a runtime server registered under the Dev MCP's name: the `ping` that answers is its own, and only its tools are present [S34]. Working form: preflight with a design read (`listRecordTypes`), a check that the design tool families are loaded, and `getDevMcpVersionInfo` to confirm which server generation answered. **What expiry itself looks like depends on the server generation** (`toolchain.md` §1). Previous generation (the `~/lcp-mcp-server` checkout, state under `~/.appian-mcp/`): the practical recovery was a full quit and relaunch of the desktop app. Current generation (DevMCP 26.6.90, verified from its source): the server detects the expired session — a 401, a 403, or an HTML bounce on the JSON path — clears the stored cookies unconditionally, reopens the browser sign-in window, and retries the call itself; and it ships a `logout` tool that deletes the session and the browser profile so the next sign-in is a genuine one with MFA. Quit-and-relaunch now cures only a wedged server process — tools absent while `ping` is green, or no sign-in window appearing when one is due — never expired auth.
- **A verification that reads a cache is not a verification of the file.** A stale `__pycache__` served an old module to a test that then passed. Working form: compile source text each run.

## B. Writes that do less than they claim

- **A single Write Records node targeting two record types across different data-source handles writes nothing** — COMPLETED, `error: null`, zero rows for every type in the payload including the one whose handle was fine. Downstream event nodes still fired and forged audit rows describing two status changes that never happened. Isolated by a same-handle control that succeeded, so the trigger is the handle split, not the multi-type payload; `a!flatten` is the correct accumulator and does not rescue it. **Proven fix:** one Write Records node per record type, chained; `ErrorOccurred`/`Error` wired on every business write; every event and notification node gated on write success with an XOR reading `a!defaultValue(pv!err, false())`, defaulting to End. Proven by break-test: a forced oversize write returned COMPLETED with `err = 1` and no event row.
- **`append()` onto a strongly typed record list silently drops rows of any other record type.** No error, `onSuccess` fires, the write does less than it claims. Working form: `a!flatten({ {parentRow}, childListA, childListB })` is the only safe multi-record accumulator.
- **A single-record brace list types itself and drops child rows.** `{ 'recordType!X'(...) }` with one member is homogeneous, types itself `List of X`, and is as lethal as a typed list while looking safe; nested appends onto it discarded every child row on every launch. It also flattens inside an expression and does not flatten across a process-variable boundary, so a node can receive a list-of-list and pause. Working form: a brace list is Any Type only if its members differ; stage bare records into single-valued PVs; `a!flatten` on every `Records` input; verify by counting child rows per parent after exercising the real control.
- **A nested related-record write fills only the foreign key of the relationship it was nested through**, so rows keyed for security on a different FK were written invisible to everyone, forever, with the sequence consumed and no error. Working form: chained Write Records nodes joined on natural keys; a sequence probe (insert with PK omitted, read the key, delete) to detect invisible rows.
- **Client-side key allocation over a row-secured type overwrites another scope's row.** `max(id)+1` computed from the rows you can see produces a key an invisible row already holds; `a!writeRecords` updates on a present key, so the collision is a silent overwrite, not an error. Working form: never mint keys client-side; let the source assign them; take FKs from relationships or from `RecordsUpdated`. Fixing the accumulator without fixing the key allocation turns a one-row overwrite into a many-row one; fix both together.
- **`tostring()` on a list collapses it to one joined string and zeroes join keys.** `tostring({"a","b"})` is `"a; b"`, not a list; `wherecontains` against it is a guaranteed miss, so a foreign key derived through it was written null on every row of every launch, and a downstream roll-up with an empty key set wrote zero rows, silently. `tointeger()` maps element-wise; `tostring()` does not. Working form: `a!forEach(items, tostring(fv!item))`; never pass a list to `tostring()`; A/B the fix against an un-repaired control.
- **Column ALTER is a no-op that returns 200.** `updateRecordTypeField(length: n, updateTable: true)` bumps the version, changes the reported type, and leaves the physical column untouched (worked exactly once, then never again across five attempts on three fields); Designer type flips behave the same. Working form: only CREATE applies a width; widen by drop-and-recreate, then repoint every reference by the new field UUID and re-render each dependent (a dangling field UUID saves clean and renders empty). (both builds)
- **A partial-row Write Records payload does not null omitted fields**, so a partial write cannot clear a field. Working form: write `null` explicitly for fields you mean to clear.
- **Turning `CaptureEvents` on at a node whose payload names more than one record type writes no events and no error.** Working form: a separate event node after the business write, one base-type row by primary key.
- **An event payload with a null primary key inserts a phantom row instead of logging an event.** Working form: guard every event payload on a non-null id.
- **A scalar Document field receiving a multi-document input keeps one and drops the rest**, on every launch. Working form: a child record type for documents.
- **A document UUID written into a document column lands as the invalid-document sentinel** (`-2147483647`) without erroring. Working form: resolve the numeric id through a Document-typed constant and `tointeger()` before writing.
- **Process node properties given as expressions where a value is expected mean the opposite.** `CaptureEvents` as `=false()` is read as conditional capture (then demands event types and fails 400 — and the failed create persisted the node); `PauseOnError` as `=false()` reads back `value: 1` beside the expression. Working form: set these by value.
- **Subprocess node inputs are PV name mappings, and the API rewrites what you send.** `"myVar"` stores `pv!myVar`; `=pv!myVar` stores `pv!pv!myVar`; a literal stores nothing; an expression stores `pv!<expression>` and maps nothing — all HTTP 200, and the subprocess completes with null inputs. Working form: bare PV names; compute values in a preceding node's `customOutputs`; read every mapping back.
- **`errorAlertGroupName` passed to `createProcessModel` returns success and does not persist**; `updateProcessModel` rejects it. Working form: set the alert group in Designer and confirm by readback. **26.6.95:** the parameter is now `errorAlertGroupUuid`. Whether it persists is unmeasured, so the working form stands until a create proves otherwise.
- **A derived "dirty" counter never reset after a save leaves the button live; a re-click relaunches and mints a duplicate audit row.** Working form: reset the originals in `onSuccess`.
- **A second write path to the same data that skips the shared recompute leaves derived aggregates stale while the trail records the change.** Working form: every write path calls the single implementation.

## C. Readbacks and metadata that misreport

- **Column widths are misreported in both directions.** After an ALTER, `getRecordType` reports the requested width on a column that never changed (255 reported, 50 physical). On another instance the same readback reported VARCHAR(255) for a column that stored 4000 characters intact, so a cap set from the readback would have clipped silently. A `createRecordType` call silently ignored a nested `fields[].length` and created 255; an `addRecordTypeField` create response under-reported a width that a 296-character write then proved. Working form: neither direction of a width readback is evidence; measure by writing N and N+1 through the production write path (a throwaway process model with a Write Records node), and set truncation caps equal to the measured column. (both builds)
- **Document metadata is not the object's state.** `getDocument` and `listFolderContents` report `extension: null` where runtime `document(doc, "extension")` returns the real value; a document constant reads back as a string; `document(id, "folderId")` is empty pre-submission by design. Working form: resolve document facts at runtime. (both builds)
- **A create response can omit relationships it created** (`relationships: null` beside `relationshipsWired: success`), specific to create-with-relationships. Working form: confirm by readback before "fixing", or you create a duplicate.
- **`createConstant`/`updateConstant` do not enforce the declared type.** A JSON number into a TEXT constant (or a quoted number into a NUMBER one) returns 200, reads back happily, and makes the object unopenable in Designer (HTTP 500). Working form: read the constant back and check the JSON type of `value`. (both builds)
- **Integration expressions read back with legacy versioned function names** (`a!toJson_17r1`, `a!fromJson_19r2`) that are rejected if pasted into a rule, yet the stored call runs; **integration booleans set `false` read back `null`**, and so do some enumerated properties. Working form: a readback of an integration is not a copy of it — verify the body by evaluating the as-sent text in a throwaway rule, verify flags visually in Designer, and treat one live call as the proof.
- **Connected-system auth readback does not show what is sent.** The readback showed a header named `Authorization` with an empty value while the live object sent a header literally named `Bearer`. Working form: only the receiver's error quoting the request proves headers.
- **Expression readbacks come back compiled** (`rule!X(` → `#"<uuid>"(`, field references as `rv!record[#"urn:appian:record-field:v1:…"]`, site expressions in `#"urn:appian:function…"` form), so an authored-versus-readback string comparison always fails, and a "did the tool rewrite my expression" scare is usually the echo form. Working form: verify behaviourally (a rendered label present or absent), and re-read stored forms with the listing tool that returns aliases.
- **A record type's field list under-reports the external table** — it shows mapped columns only, so absence in the record type is not absence in the source. Working form: describe the table in the source system before any claim about its shape.
- **`getObjectSecurity` returns only administrator, editor, and viewer** for process models — absence of a role in the response is evidence the API does not report it, not that it is unassigned. A security readback can also **agree in effect and differ in mechanism**: a group listed as viewer on an object may inherit it from the folder, which also covers every other inheriting object there. Working form: state direct versus inherited.
- **`listGroupMembers` returns an empty display name for every user.** Display names are a Designer check.
- **Reorder tools echo expressions in UUID form** that looks like a silent rewrite and is not. Working form: re-read with the listing tool.
- **A closed log entry recorded from memory recorded the wrong object version.** Working form: versions and states are stated from readback, never from memory; the readback is the record.
- **A binary's symbols are metadata, and they misreported a tool's command surface in both directions.** A static read of the sail binary:
  - reported a `whoami` command that does not exist (the name belonged to an internal method);
  - missed the `navigate` command and the `--json` flag;
  - credited record-view and related-action following to the wrong command [S3].

  `--help` listed the real surface. The help is a claim too: `navigate`'s help says a target may be shortened with or without its `⤴` marker, but a shortened target without the marker failed where the same prefix with it resolved [S3]. Working form: symbols and schemas are hypotheses. Read the help, then measure behaviour, and record which of the three a statement rests on.

## D. Validators and renders that pass broken things

- **`validateExpression` is not a keyword check.** It accepts keywords the object validator rejects (`contentsWidth` on a header-content layout, `truncateText` on a grid column, `shouldWrap` on a side-by-side layout, arbitrary nonsense on some components), resolves a rule name but not its parameters, evaluates both branches of an `if`, cannot touch the user service or `document()`, and returns errors only. Working form: only the object validator (`updateInterface`, `createExpressionRule`, `validateDesignObject`) is authoritative; a "what does this return" question needs a rule or interface you actually run. (both builds)
- **The rendered tree is not a parameter list.** Attributes that appear in a render (`numberOfLines`, `hideSearchButton`, `truncateText`, `decorativeBarColor`) are output state, not accepted inputs; setting them fails at save or, worse, is dropped. Working form: verify a parameter by the object validator and docs-search, never by its presence in a tree. (both builds)
- **Some writers do not validate keywords at all.** `createSite`, `updateSite`, and `addRecordTypeAction` accept a misspelled keyword (`groupsToCheck:` for `groups:`); the function evaluates with the argument missing, returns false, and silently hides the page or action it gated. A page `width` key is accepted with 200 and dropped. Working form: read the stored expression back and confirm the keyword, then click as a member and a non-member. (both builds)
- **A component passed into a Text-typed parameter validates clean and renders its serialized object graph** (`a!gridColumn(value:)` and `(label:)`), while the same mistake in a rich-text position errors loudly. Working form: wrap in a rich text component and carry links on `a!richTextItem(link:)`.
- **A hidden component's expressions are unevaluated.** Anything behind `showWhen: false`, an inactive wizard step, a toggled grid, or a view-switch local is not proven by a clean render; a change that later reveals it runs untested code. Working form: flip the default to the hidden branch, render, restore, verify the restored source byte-identical, re-render. (both builds)
- **`a!wizardLayout` evaluates only the active step**, so type errors in later steps save clean and fail on first Next; step properties (`disableNextButton`, `validations`) are invisible to every render route. Working form: a generated companion harness per step, regenerated with the source; a throwaway truth-table rule for each gate.
- **The record-view validator evaluates with a null identifier**, so a view that renders perfectly under `testInterface` fails at save time on any `=` filter fed from the record; the same null reaches related-action visibility expressions, which throw silently and hide the action. Working form: guard the whole block on a `hasId` local; null-guard every visibility expression; verify by clicking.
- **Test inputs are literals.** `testRule` and `testInterface` do not evaluate an expression passed as an input (it renders as though empty); `testInputs` on `createInterface` do not apply to the validation render; `testInterface` without explicit `inputs` renders nulls even when test values are saved on the object. Working form: pass inputs explicitly; verify query-dependent objects through a wrapper interface. On DevMCP 26.6.90 the `testRule` and `testProcessModel` tools say so in their own descriptions (send text as `abc`, not `"abc"`) and name the temporal formats they accept.
- **A generated verification harness goes stale silently and positively**: it keeps rendering `error: null` against a screen that no longer exists, and a hand-maintained unused-locals list rotted until the generator could not produce a valid interface at all. Working form: regenerate in the same change that edits the source; compute derived lists from the source (comments stripped before counting); before trusting any render, confirm a string you just changed is present and the old one absent. (both builds)
- **A check with nothing to verify passes and inflates the headline count.** A quote check that skipped when no prose was uploaded, a date guard that nulled every value so the comparison compared nothing, an aggregate reconciliation whose components were each wrong but summed right. Working form: fail closed when evidence is absent; every check gets an input that must fail; recompute per item; make assertions two-sided (expected value present, default absent).
- **A single omitted field in an otherwise-correct `fields:` list returns null with no error** — correct row counts, working screen, every row showing the same defaulted value. Omitting `fields:` altogether returns only the identifier, also with no error. Working form: always pass `fields:` including related fields, and check that a value which should vary actually varies.
- **Your own extraction tooling can misreport a render** (a parser expecting one JSON separator reported zero matches). Working form: validate the parser against a known-present string; distinguish "the harness says zero" from "there are zero".
- **Hand-copied figures from a tool result produced a false finding.** Working form: never transcribe data for analysis; read figures straight from renders or regenerate them.

## E. Row-level security and identity

- **Row-level security filters every read silently**, with no marker distinguishing absent from invisible — `listRecordData`, `a!queryRecordType`, counts, `min`/`max`, `.totalCount`, related-record traversals, data-fabric SQL. A complete seed was diagnosed half-loaded, a Blocking item raised, and a reload proposed, all artifacts of the reading account's group membership; a zero orphan count proved nothing because parentless rows are invisible, not present-and-unparented. Working form: every readback states the account and group scope it ran under; re-read as a member of every scope before concluding absence; prove absence another way (a PK insert that succeeds proves the id was free). (both builds)

  **The trap reaches past row security, and it runs both ways.** Measured on one site, read through sail as the design account and as a persona [S32]:

  - the record list returned the same 8 rows to both accounts;
  - the design account saw 8 pages to the persona's 2;
  - two security-aware KPI roll-ups read 126.01 and 54.5 against the persona's 94.41 and 22.9, and both gaps were exactly one restricted record's value (31.6);
  - that record's values were real for the designer and `Restricted` for the persona, in a grid and on its record view;
  - the record view offered the designer 29 actions to the persona's 26;
  - one related action was offered to the persona and "none available" to the designer.

  A designer readback over-reports what personas see and under-reports what they can do. Working form: persona-scoped reads through sail, one data directory per persona, every observation stating its account (`patterns.md` §12).
- **A row-security filter and a broken relationship render identically** — empty, `diagnostics.error: null` — as does an omitted `fields:` list and a record-data agent tool that does not traverse. Working form: verify traversal only as an in-scope account with an unsecured sibling as control.
- **Writes and deletes targeted by primary key succeed against rows the account cannot read.** Useful for restoring another scope's data; a trap if invisible is assumed to mean absent, and the reason a drop-recreate nulls rows you cannot see (restore from the authored source, not from a readback). (both builds)
- **A related record the user cannot see nulls its fields silently rather than erroring**, so a case and its parent must carry the same scope or the parent's name simply blanks. A null foreign key under a RELATED_RECORDS rule is visible to nobody.
- **Two MCP servers for one platform share one tool namespace with different executing identities, and tool names do not announce their server.** Under the foreign service-account identity, row-secured reads return empty while PK-targeted writes succeed: a process completed green having read nothing, the agent fabricated a confident assessment over an all-empty context, and the process wrote a status change, a comment, and an audit event — a forged audit trail with every error variable green. The tell: text composed from the process's own parameters was correct while every record read was blank. Working form: establish which server and identity each tool family runs as (camelCase unprefixed versus snake_case product-prefixed plus `ping`); ban the foreign family for design work; confirm identity with a throwaway `loggedInUser()` rule; a context-resolved gate before any agent node. Name the servers by role, so every tool's name carries its server (`toolchain.md` §2). With both registered under one name, one session carried only the runtime server's tools under it and another carried both sets merged [S34].
- **Two tools can read the same table under different identities and disagree silently** (a data-fabric SQL tool returning zero rows where `testRule` returned seven). Working form: every readback names the tool as well as the identity.
- **Connected systems, integrations, and agents run under their own credential, not the session's.** A process-side context assembly runs under the process initiator's scope, so a scope-limited presenter's intake silently finds only their own scope's rows; an agent identity outside the scope groups sees empty traversals; a design account that can read everything proves nothing about personas. Working form: state which identity a probe ran under; grant the operator group the scope the flow reads under; verify as a persona.
- **A document the viewer cannot read raises an expression error in `a!richTextImage`/`a!documentImage` that takes down the whole page**, invisible to validation, `testInterface`, and any design-account render — it appears only on a persona login. Working form: assets in the consuming application's own folder, or behind a switchable fallback constant; a shipped asset never depends on another application's object.
- **A group that contains the right user can still be the wrong group** — it also contained the designer account, so gating on it would have hidden the pages from the person verifying the change. Working form: read the membership list before choosing a gating group.

## F. Process models and the Execute AI Agent node

- **Agent input keys that do not match the agent's declared variable names are silently ignored (case-sensitive).** A `caseId`/`caseID` mismatch ran the agent with no input; the run COMPLETED with an empty output map and downstream routing proceeded on zeros. The declared names cannot be read over MCP. Working form: exact names from the builder or Designer; stop rather than guess spellings.
- **An ACP bound in a user input task's form `inputMap` is forced `required: true`**; `required: false` and omission are both silently ignored with 200 and a `true` readback, and a legitimately null source then throws at submit on every successful run. Working form: guarantee a non-empty value with `a!defaultValue`.
- **An empty-string second argument to `a!defaultValue` in a Send E-Mail body is dropped on save** and errors at runtime with "Too few parameters"; a bare `pv!` in the body fails with `begin 0, end -1`. Working form: non-empty defaults, values wrapped in a function, node read back to confirm both arguments survived.
- **An error on an unattended node does not set the process to Paused by Exception**, so a stranded instance looks merely "still running"; a paused node placed ahead of the row that records progress stalls invisibly. Working form: open the run row before anything that can fail; `PauseOnError: true` for audit writes.
- **A refused attended-model run arrives as a bare `Network error:`** (and HTTP 500 from the runtime invoke tool), both reading as infrastructure faults. Working form: check the model for a user input task first. Measured on the previous server generation; on DevMCP 26.6.90 `testProcessModel`'s own description states it works only for unattended models, and attended tasks have their own tools (`mcp-capability-boundaries.md` §4).
- **The events parameter's `comment` is one expression evaluated once per node**, so a bulk write spanning several parents stamps the same sentence on every trail. Working form: build event rows per parent in a script task and write them with `CaptureEvents` off.
- **A hardcoded audit sentence written when one path could reach a lane asserts a false rationale once other paths can.** Working form: compose detail at write time from values in hand, reason-aware.
- **`a!startProcess` does not expose `fv!error` to `onError`**; write a self-contained failure message. **A send or notify node after a write cannot roll it back**; attach notifications as new downstream nodes.

## G. Sites and record configuration

- **`updateSite` persists what you send without landing it.** The pages array is a full replacement that regenerates every page UUID and web-address identifier, including untouched pages, orphaning every stored `a!urlForSite` reference and bookmark; a page `width` key is accepted and dropped; a wrong keyword in a visibility expression is stored verbatim and evaluates false; a visibility expression stored correctly on a page gated by a group that MCP cannot populate shows to nobody. Stored and landed are different facts, and only the second is provable — as the intended user, through sail's `pages` for a persona with a local account (it lists exactly the pages that account can see [S4]), or in the browser. Working form: `getObjectDependents` on the site before writing; read the site back and repoint every page reference; verify visibility behaviourally. (both builds)
- **`relatedActionShortcuts` accepts an order and ignores it**, returning the record type's own action order. Working form: reorder on the record type in Designer and read back with `listRecordTypeActions`.
- **Record types created over the Dev MCP have no views**, not even the default Summary. Working form: add a Summary view with `nameExpression: ="Summary"`.
- **Generated record lists default to raw foreign-key integers**, with nothing erroring. Working form: columns in Designer, or interface pages with record-bound grids.
- **A dropdown's `saveInto` that clears another field's targets in its else-branch erased a working autofill**; the tell is a `null` in an else-branch. A user picker holds a list, so a scalar user column compared with `loggedInUser()` never matched.
- **A primary button without `submit: true` did nothing, with no error, for weeks.** Working form: diff the control under test against a working sibling in the same render; audit siblings after each defect class.
- **A related-action delete threw "record does not exist" on both Delete and Cancel while every delete had succeeded** — the record was destroyed inside the start form's submit `saveInto`, under the framework's post-submit context. The constant identifier in the error was the action's own token decoded as a record id. Working form: Start → XOR on cancel → Delete Records node → End, unchained; an error dialog is not a result — read the data.
- **Masking at the display layer leaves the sort order leaking the real value.** Working form: field-level security in Designer is the real enforcement; `showWhen` is a demonstration.
- **Masking implemented in interfaces leaves the record type's other surfaces unmasked.** A restricted record's four sensitive fields read `Restricted` to a persona in a dashboard grid and on the record's view, and in clear on the site's record-list page: one record type, one persona, one session [S33]. The design account sees real values on every surface, so from the design seat the three surfaces agree and nothing looks wrong, and no validator or render reports it. Working form:
  - When data is genuinely restricted, enforce it at the data and security layer (record- and field-level security, a Designer step; `mcp-capability-boundaries.md` §2), so every surface inherits it.
  - Treat interface masking as display.
  - Sweep every surface of the record type as each persona before a showing (`patterns.md` §13).

## H. Expressions that answer a different question

The supplemental skill §4 carries the full measured list. The ones that shipped defects:

- **`.totalCount` returns -1** (both builds; not batch-size-dependent), rendered as a confident wrong number. Working form: `a!aggregationFields` with a COUNT measure.
- **`count()` returns 1 on a list of dictionaries**; a check gated on it skipped itself and passed.
- **`index(map, key, default)` cannot tell "key absent" from "value equals the default"**, so a consumer handed the wrong map shape produced a complete, plausible, entirely wrong result with clean diagnostics. Working form: assert the shape on one mandatory key.
- **A `queryFilter` whose value is an empty list is ignored and returns the whole table.** Working form: guard `in` filters; fall back to `{-1}`.
- **`text()` truncates rather than rounds, groups thousands only as literally spelled and returns `"N/A"` beyond that, and misplaces the sign** (`13-0`, `11-5.3`); `text(<Date as text>)` returns the sentence `Date out of range (-N)` without erroring and ships it into a cell; `todate()` on an ISO string is a sign inversion. Working form: `round()` first, one group per magnitude, `abs()` plus a word, real Dates for arithmetic.
- **A Date passed into a Date and Time input is coerced to midnight and display-shifted a day back.** A timezone-less external timestamp is read as UTC while the source session clock may not be UTC, so a column default stamped session-local time read hours old.
- **`a!fromJson` coerces ISO date strings to Dates**, so a string-length guard nulled every value and the check passed on nothing.
- **A locally-sourced grid identifies rows by position**, so a business-key `selectionValue` highlights nothing with no error.
- **A grid's rendered `totalCount` is a look-ahead of page+1**, not the total.
- **A "return everything" decision expires silently when the data set it was reasoned about splits** — still a correct superset, no test fails, cost surfaces elsewhere (an unfiltered reference list tripled an agent's reasoning time). Working form: write the coincidence into the comment that justifies the decision.
- **Saving a list of Text into a local mid-wizard destroys the form instance** with no error (root cause never found). Working form: a delimited scalar with delimiters at both ends.
- **Casing is not a mapping**: title-casing an enum produced `Fx_forward`; substring matching on event names credited the model's judgement to plumbing. Working form: explicit display rules break-tested on every stored value plus null and an unmapped value.

## I. Integrations and connected systems

- **"Automatically convert to JSON" showed checked and still sent Appian's text rendering of the map**; the receiver rejected it with a 400 and Appian raised nothing. Working form: the body expression returns the finished JSON string via `a!toJson(map, false)` with auto-convert off.
- **A name-addressed runtime invoke tool reports "not found or not accessible" under a foreign identity** — an access symptom, not a missing object.
- **A record type over an external source with no per-user default compute setting fails every query** with a message that reads as a connection fault. Working form: per-user setup steps in the SC setup doc.

- **A pre-submission upload is readable by expression tools and not by an agent's document tools**, and a replaced document is invisible to an agent until indexed (minutes) — the agent does not report a missing document, it reasons without one. Working form: agents read only permanent documents; replace first, leave a gap, verify with a mechanical quote check.

## J. Agents and LLM outputs

The run-summary finding below is documented in full, with the observation series and the resulting rule, in `reference/model-output-verification.md`.

- **The Execute AI Agent node's `RunSummary` does not describe the run and fabricates one.** Identical boilerplate on successful runs; then invented entities, invented rules, "successfully executed" claims for actions that never happened, and a confidence figure contradicting the actual output — across ten observations and four instruction states, including a reversal of an earlier closure made on two clean runs. Working form: capture it to a PV, consume nothing from it, never surface or diagnose from it; diagnose from structured outputs and Agent Studio's trace.
- **An Agent Studio record-data tool returns the backing record type's own fields only; related fields are simply absent** — byte-identical to an omitted `fields:` list and to a row-security filter, which is why it took two sessions to see. Working form: assemble context process-side into one labelled text input.
- **An agent applies a stated numeric test qualitatively unless told to compute it** ("a contributing pressure… the window is workable" beside a lag larger than the window). Working form: require both numbers and the comparison in the output.
- **An agent folds an upstream model score into its own confidence, and counts the case's premise as a concern, unless the output description excludes them by name**; an open-ended list of concerns produced variance straddling a threshold (0.78 and 0.87 six minutes apart on identical input). Working form: closed lists, explicit exclusions, replicate before acting.
- **Agent rationales assert false relationships between the agent's own proposed numbers while every external check passes.** Working form: "state the computed number or say nothing" plus self-consistency checks.
- **An agent returns JSON preceded by prose regardless of instruction**, so every run failed the parse gate and fell back while the agent worked perfectly. Working form: discard everything before the first brace; strip the last-brace tail the same way.
- **A default fallback on a tool's document parameter returned another client's data**, and a folder tool let the agent quote a staged document into a different client's plan while sixteen checks passed. Working form: documents bound to inputs, no fallbacks, one extraction rule shared by agent and checker.
- **Tool-description economy does not stop corroboration calls**: an agent told to prefer the cheap tool still spent the expensive one verifying a correct answer. Working form: an explicit prohibition.

## L. Fixtures, harnesses, and process — self-deception

- **Fixture prose authored beside the row, not composed from it, puts fiction on a faithful screen**; an invented figure survived four passes in a table nobody had rendered. Working form: compose from stored values with the screen's own rounding; audit every table including event history.
- **A re-date script's docstring promised three output files and its `main()` wrote one**, so two tables were re-dated by hand for several passes against a script that looked complete. Working form: assert every output exists; prove idempotency by byte-identical regeneration.
- **A verified before-state makes an unverified after-state look verified** ("WIDENED, verified at 255" was false). Working form: re-probe after every change; a log row states what was measured and when.
- **A claim written into code from an early readback was disproved by a later row.** Working form: comments state only what is provable, and a false note is worse than no note.
- **Grep-based audits miss text composed inside process nodes**, and a count-only palette audit answers a different question from a located one. Working form: read each render site and the composing nodes; census by rendered tree per screen state.
- **Live reference data diverged from the repo canon** (a hand-added row inflated every quoted count). Working form: reconcile environment reference tables against canon files before quoting counts.
- **A process parameter's existence is not proof it is consumed** and a model can have no caller at all. Working form: read the nodes; prove callers with `getObjectDependents`.
- **The docs-search token expires without warning** and the server drops out of the session; a grounding step silently skipped is a layout edit made on guesswork. Working form: say so, measure on the instance, re-authorize afterwards.
- **A GNU-only regex token in a macOS `sed` pipeline is accepted without error and matches nothing, so the filter after it filters nothing.**
  - **What happened.** A tool-inventory count extracted names with `sed -E 's/^\s+async def …/'`. macOS's BSD `sed` has no `\s`, so no line was reduced to a name. The `grep -v "^_"` meant to exclude private helpers therefore excluded nothing, and three helper functions were counted as tools. The same token had worked in the pipeline's `grep`, so nothing looked wrong.
  - **What it cost.** The inflated counts were committed to the boundaries doc: 160 against a true 157 for the current server generation, and 148 against a true 145 for the previous one. They survived until a three-tool discrepancy with the live server was reconciled by diffing the decorated tool names against the server's own tool list (measured and reproduced on both installs, 2026-09-21; `mcp-capability-boundaries.md`, tool count note).
  - **Working form:** any count that reaches a doc is cross-checked against a second source (here, the server's live tool list). On macOS, use POSIX classes (`[[:space:]]`) rather than GNU shorthand such as `\s`.

## M. The sail CLI

Measured in one evaluation against a live site (`examples/persona-verification-walkthrough.md`; the S-numbers are its measurement record). sail's own headlines are often candid — "⚠ Nothing changed", "the page below is as it was before the form opened" — but its exit codes and its listing are not, and an agent reading either is misled.

- **A submit that validation blocked exits 0 with `✓ Interacted`.** Blanking a required field and pressing the submit button in one batch printed the success headline, a `⚠ A value is required` line, and the field as `[REQUIRED INVALID]`, with the form still open. Under `--json` it returned `status: "ok"`, `movedNothing: "True"`, and a `validations` list [S12]. Working form: read the ⚠ lines, the field states, and `validations`. A submit is proven only by a fresh read of its target.
- **A disabled button is sent anyway and exits 0.** Driving a `[DISABLED]` button printed "⚠ Nothing changed … the server accepted the interaction and no value moved" [S16]. Working form: treat "Nothing changed" as a failure to drive the component, as sail's help says, whatever the exit code.
- **An out-of-range dropdown index clears the field and exits 0.** Index 99 printed `✓ Interacted` and a diff taking the field's value to `(empty)` and re-disabling the button that depended on it. Index 0 and text values were refused before sending, and `-1` was parsed as a flag [S17]. Working form: take indexes from the `choices:` line of the current listing, and check the diff for the value you meant.
- **A batched picker pick is dropped silently when an earlier pair restructures the form.** Selecting a category and a picker suggestion in one command printed `✓ Interacted`. The category change loaded an existing record into the form and removed the picker, and the pick vanished without a mention [S18]. Working form: batch only fields the current listing contains and that nothing earlier in the batch can remove. After a restructuring change, re-read the listing and drive the next field separately.
- **A submit prints the pre-form snapshot, so a successful write reads as if it did not happen.** The success headline carries the process id and a note that the page below is as it was before the form opened. That page, and `show` afterwards, still showed the old value [S13]. Working form: navigate to the record or page afterwards and read it fresh. Where the app has attribution, confirm the activity entry naming the acting user.
- **`load --fresh` reloads the site's default page, not the record just written.** It is the reload the submit's own note suggests, and it lands somewhere else [S13]. Working form: `load <site> <page>` for a page, or navigate back to the record through its link.
- **The listing hides rows and values the YAML holds.** A grid is previewed as its first two rows and "+N more". A restricted record sat in row 7 of 7, so its masked cells, and the difference between two accounts' views of them, appeared only in the YAML [S7, S32]. Tag values (8 of 8 on one record view), milestone names and dates, and a changed sort order were YAML-only too [S7]. Working form: answer every question about values from `<site>-ui-concise.yaml`, not from the listing.
- **Under `--json`, errors are plain text on stderr and stdout is empty.** A refused target and a confirmation refusal both exited 1 with 0 bytes on stdout [S19, S23]. Working form: check the exit code and stderr before parsing stdout.
- **Ordinal refs renumber after a re-render.** Three disclosure links were `⌗ … 1`, `2`, and `3`. Expanding the first renumbered the other two to `1 of 2` and `2 of 2`, so a stored ref now names a different link [S22]. Working form: re-read the listing after any interaction that can add or remove siblings, and never replay ordinal refs from an earlier listing.
- **An imported session is the Dev MCP's own server session, so `sail logout` revokes both.**
  - `--from-devmcp` copied the Dev MCP's cookie file; all three cookie values were identical.
  - After `sail logout` on the import, the Dev MCP's file was byte-identical but its session was dead. A probe import reported it "no longer valid", and the Dev MCP server's next call hit a 401, reopened its browser, and recaptured a session in 3.1 s [S30, S31].
  - That recovery was silent only because the browser profile's identity-provider session was still alive. Without it, the Dev MCP's next call lands an SSO and MFA prompt in the middle of a build.

  Working form: import only for deliberate designer-versus-persona diffs, into a throwaway data directory, and discard it by deleting that directory, never by `logout` (`CLAUDE.md` §6).
